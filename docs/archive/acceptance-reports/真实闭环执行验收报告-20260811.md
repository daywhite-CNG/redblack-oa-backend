## 本轮变更

- 前端默认 `VITE_API_MODE=real`，通过 `VITE_API_BASE_URL=/api/v1` 访问后端；真实模式不导入 seed、不生成 Mock Token，也不使用 `OaContext` 作为本地业务数据库。
- 新增统一原生 `fetch` 请求层，集中处理 Bearer Token、`X-Request-Id`、`Idempotency-Key`、JSON、multipart、Blob 下载、取消请求以及 401/403/4xx/503 提示。
- HTTP 非安全上下文中也生成标准 UUID 格式的请求 ID 与幂等键；避免后端拒绝不符合 UUID 约束的公告发布请求。
- `SELF` 数据范围的员工用户选择器返回本人部门的最小用户引用集，以支持必填的工作交接人；详情页直接保留后端返回的领导和交接人名称，不依赖员工无权读取的用户管理列表。
- 公告详情的已读请求只更新本地公告状态，不再触发全局用户、组织、审批和公告数据重载，避免点击公告后的页面闪动或重复刷新。
- 各业务列表筛选区原“重置”操作统一调整为“刷新”：保留当前筛选条件，仅重新读取真实服务数据。
- 登录、组织权限、请假审批、工作台、公告通知和附件页面改为调用真实 API；页面不以假数据填补无权限或接口失败结果。
- 附件下载先完整读取并校验长度、SHA-256、ETag，再重新打开对象流输出。公开附件响应不包含 Bucket、Object Key、ETag 或凭据。
- Nginx 已配置为同时提供前端静态站点与 `/api/v1` 反向代理；生产页面以同源 `/api/v1` 访问虚拟机服务。
- 文档同步了真实模式、`FILE_STORAGE_UNAVAILABLE` 契约、部署来源核验和两次读取下载语义。
