# Evidence v1：验真与结果语义

验真是**只读**行为；不得在验真请求里补写链、改审批事实或生成新证据。P1 仅冻结语义，尚无验真 API/服务实现。查询前沿用 OA 对申请/证据的对象级权限；无权访问时直接返回授权错误，不泄露 `NOT_FOUND`、证据摘要或链状态。

## 比较对象

使用经授权取得的已冻结源快照（含 17 字段规范化负载、原始附件 `fileId/sha256/sizeBytes`、前一证据引用）和指定 FISCO 群组/合约的链上记录。按原 `schemaVersion` 和原 HMAC 密钥版本逐字节重建 canonical bytes、附件根、`evidenceId` 与 `evidenceHash`，再比对全部链上承诺字段、前序链接、动作/状态/轮次、时间和时间线位置。只比对传来的摘要字符串不足以证明 MATCH；不能用当前可变 OA 行或当前文件代替冻结快照。链上仅能证明某授权 writer 曾提交该承诺，不能独立证明原始业务事实真实。

交易收据若已保存，还应核对成功状态、目标合约地址、登记事件、`transactionHash`、`blockNumber` 与链上记录一致；收据缺失时可由链上记录和事件重建定位，但不能凭空生成交易哈希。链重组/群组错误、查询不完整或合约地址不明不能按“没有记录”处理。

## 单一结果码（优先顺序）

| 结果 | 精确定义 |
|---|---|
| `UNAVAILABLE` | 获授权后，所需链节点/群组/合约或可信链下快照源不可读、超时、返回不完整/不可判定结果。不得推断不存在或匹配；保留错误来源。 |
| `MISMATCH` | 两侧可读且链上该 `evidenceId` 存在，但任一规范化字节摘要、附件根、前序链、动作/状态/轮次/时间、合约地址或收据事实冲突；或本地同一 ID 对应不同不可变快照。返回差异类别，不泄露敏感原文。 |
| `MATCH` | 两侧可读，链上存在，原版本重算及所有承诺/顺序/已知回执均一致。即使本地投递状态仍显示 PENDING，也以链上事实为准，同时另行触发回执状态修复流程；验真本身不改状态。 |
| `PENDING` | 本地有完整、有效、不可变快照，链上明确不存在，且投递/交易仍等待、回执未知或可重试处理中。终止失败不能无限期伪装 PENDING。 |
| `NOT_FOUND` | 链查询明确可用且不存在，同时本地已声称 CONFIRMED 或已结束处理；或经授权本地根本没有该证据/冻结快照。响应附 `missingSide=ON_CHAIN`、`OFF_CHAIN` 或 `BOTH`（两侧均不存在），不能把一侧缺失说成 MATCH。 |

分类步骤：先授权；再确认本地快照源与目标链可读（否则 `UNAVAILABLE`，明确确认本地无该 ID 不算不可用）；若链上存在且链下记录存在，重算并得 `MATCH/MISMATCH`；已读取但字段非法、摘要无法按 v1 重算属于 `MISMATCH`，不是 `UNAVAILABLE`。若一侧确定不存在，按上表的本地处理状态得 `PENDING/NOT_FOUND`。链上存在而本地确定无快照为 `NOT_FOUND (OFF_CHAIN)`，需告警且**不是**链上匹配。链上不存在、但本地终止失败/明确 CONFIRMED，为 `NOT_FOUND (ON_CHAIN)`；两侧均明确不存在为 `NOT_FOUND (BOTH)`。若源字节缺失但存储暂不可读，属于 `UNAVAILABLE`，不等于确定不存在。

`MATCH` 不宣称 OA 操作者真实授权、附件未被替换、业务内容真实或 P0.5 Docker 已通过；这些需业务源、文件原文复核与运行验收另证。查询输出不得泄露 HMAC 密钥、附件原文、姓名、理由或审批意见。验真日志仅记录 ID、结果、链定位和脱敏差异类别。
