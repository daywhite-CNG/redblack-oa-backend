# Red&Black OA V2 权限设计

> 适用范围：OA 业务、联盟链证据、验真、网络与合约只读能力  
> 更新日期：2026-09-18  
> 关联文档：`产品需求文档.md`、`接口文档.md`

## 1. 文档目的

本文定义毕业设计版本的身份、角色、权限标识、数据范围、对象级规则和服务鉴权责任。权限设计同时覆盖传统 OA 与联盟链能力，但不把联盟组织、OA 部门和系统角色混为同一概念。

## 2. 设计原则

1. 默认拒绝：没有明确授权即无权访问。
2. 后端强制：前端隐藏菜单或按钮不是安全边界。
3. 最小权限：角色只获得完成职责所需能力。
4. 数据与功能分离：有接口权限仍须通过数据范围和对象级校验。
5. 职责分离：审批、证据审计和链运维不能由一个专用角色自动兼任。
6. 私钥隔离：任何 OA 角色都不能读取或下载链私钥。
7. 证据继承业务权限：知道证据 ID 或交易哈希不代表可以查看业务详情。
8. 服务内复核：网关完成身份前置检查，资源服务对权限和对象重新校验。

## 3. 领域边界

| 概念 | 权限含义 |
|---|---|
| OA 部门 | 决定业务数据范围和审批归属。 |
| 联盟组织 | 决定节点治理和合约写入身份，不直接决定 OA 数据权限。 |
| 系统角色 | 用户权限集合，如管理员、领导、审计员。 |
| 链服务账户 | `blockchain-service` 使用的组织交易账户，不对应普通用户登录账号。 |
| 业务对象权限 | 用户是否可以读取或操作某一申请、任务、附件或证据。 |

## 4. 权限模型

一次请求必须同时满足：

```text
有效身份
∧ 服务和接口权限
∧ 数据范围
∧ 对象级业务规则
∧ 资源状态允许操作
```

联盟链写操作还必须满足：

```text
合法证据事件
∧ blockchain-service 组织服务账户
∧ 智能合约组织授权
∧ 合约状态迁移校验
```

普通用户和管理员均不能通过 HTTP 提交任意哈希直接上链。

## 5. 预置角色

### 5.1 系统管理员 `ADMIN`

职责：

- 用户、部门、角色、菜单和权限管理。
- 查看全局 OA 业务和操作日志。
- 查看全局链上证据和联盟链概览。

限制：

- 不因管理员身份自动获得链私钥、证书和节点宿主机权限。
- 不能伪造证据负载或绕过审批状态机上链。
- 默认不能执行失败存证重试，除非显式授予运维权限。

### 5.2 部门领导 `LEADER`

- 查看管辖部门范围的申请和证据。
- 执行同意、驳回和转交。
- 对管辖范围证据执行验真。
- 不查看联盟链全局运维信息，不重试交易。

### 5.3 普通员工 `EMPLOYEE`

- 管理本人请假申请和附件。
- 查看本人申请对应的证据摘要、存证状态和时间线。
- 对本人证据执行验真。
- 不查看他人证据、网络详情或合约部署信息。

### 5.4 存证审计员 `EVIDENCE_AUDITOR`

- 在明确授权的数据范围内查询证据和业务关联摘要。
- 执行验真并导出结果。
- 查看交易定位、合约版本和验证历史。

限制：

- 不创建、编辑或审批请假申请。
- 不修改链下快照。
- 不触发存证重试。
- 不管理节点、证书或私钥。

### 5.5 联盟链运维员 `BLOCKCHAIN_OPERATOR`

- 查看网络、节点、合约和存证队列状态。
- 查看失败技术原因。
- 对符合条件的失败任务执行受控重试。

限制：

- 不获得请假审批权限。
- 默认只查看脱敏业务定位信息。
- 不提交任意业务负载或任意哈希。
- 不通过产品接口读取私钥。

## 6. 权限标识规范

格式：

```text
领域:资源:动作
```

示例：

```text
approval:leave:create
approval:task:approve
blockchain:evidence:read
blockchain:evidence:verify
```

动作统一使用 `read`、`create`、`update`、`delete`、`submit`、`approve`、`reject`、`transfer`、`withdraw`、`verify`、`retry`、`export`。

## 8. 数据范围

### 8.1 数据范围枚举

| 范围 | 含义 |
|---|---|
| `ALL` | 全部业务数据 |
| `DEPARTMENT_AND_CHILDREN` | 本部门及下级部门 |
| `DEPARTMENT` | 本部门 |
| `SELF` | 本人数据 |
| `CUSTOM` | 明确配置的部门集合 |

多角色数据范围采用并集，但对象状态和职责分离限制仍然生效。

### 8.2 证据数据范围

证据读取继承关联申请的数据范围：

- 员工：本人申请证据。
- 部门领导：管辖范围申请证据。
- 管理员：全局证据。
- 存证审计员：授权审计范围，不能仅凭角色默认跨越所有业务数据。
- 链运维员：默认只看证据 ID、状态、交易定位和脱敏错误，不自动查看请假详情。

## 9. 对象级授权

### 9.1 请假申请

- 草稿仅申请人可编辑或删除。
- `PENDING` 申请仅申请人可在规则允许时撤回。
- `REJECTED` 申请仅申请人可编辑并重新提交。
- `APPROVED`、`WITHDRAWN` 不允许覆盖式编辑。
- 管理员查看不等于可以替用户执行审批动作。

### 9.2 审批任务

- 任务必须处于 `PENDING`。
- 当前用户必须是当前处理人，或满足明确配置的代办规则。
- 同意、驳回和转交使用乐观锁防止并发重复处理。

### 9.3 附件

- 上传者可以在申请提交前管理临时附件。
- 申请提交后，附件读取继承申请权限。
- 已纳入某轮证据快照的附件不得覆盖原内容。
- 验真上传的本地文件只在浏览器计算摘要，服务器不获得文件原文。

### 9.4 链上证据

- `evidenceId`、交易哈希和区块号不是授权凭证。
- 证据详情查询必须先解析关联业务对象，再执行数据范围校验。
- 无权访问关联业务时返回 404，避免泄露资源存在性。
- 可公开展示的链网络聚合指标不得包含业务对象和个人信息。

### 9.5 验真

- 用户必须同时具有 `blockchain:evidence:verify` 和该证据读取权限。
- 验真是只读行为，不改变申请、证据或交易状态。
- 验真记录本身仅审计员、管理员和相关业务用户可见。

### 9.6 失败重试

- 需要 `blockchain:evidence:retry`。
- 证据必须处于 `FAILED` 且满足可重试错误类型。
- 重试前服务必须查询链上是否已存在。
- 重试保持原 `sourceEventId`、`evidenceId`、负载和哈希。
- 每次重试记录操作日志；不允许修改后再重试。

## 12. 前端权限行为

- 登录后读取当前用户、权限集合、数据范围和菜单。
- 未授权菜单不渲染，未授权按钮禁用或隐藏。
- 页面刷新后权限从服务端重新初始化，不依赖本地硬编码角色。
- API 返回 401 时清理会话并跳转登录；403 显示无权限；受保护资源可返回 404。
- 前端显示的 `allowedActions` 仅用于交互，不能代替后端校验。
- 存证状态和业务状态分别展示，不能以按钮文案暗示未确认交易已经上链。

## 13. 后端鉴权顺序

```text
网关清理外部伪造身份头
→ 校验用户令牌、注销状态和 authVersion
→ 路由到资源服务
→ 资源服务校验内部身份声明
→ 校验接口权限
→ 加载资源
→ 校验数据范围和对象状态
→ 执行业务
→ 写入操作日志或证据事件
```

对于链上证据登记：

```text
approval-service 产生合法证据事件
→ blockchain-service 校验事件来源和幂等性
→ 使用组织服务账户签名
→ 智能合约校验组织和证据规则
```

## 14. 服务职责

| 服务 | 权限职责 |
|---|---|
| `gateway-service` | 令牌前置校验、清理伪造头、路由和基础限流 |
| `identity-service` | 用户、角色、菜单、权限和数据范围事实源 |
| `approval-service` | 申请与任务对象级授权、合法状态迁移 |
| `office-service` | 公告、通知、附件对象授权 |
| `audit-service` | 操作日志读取范围 |
| `blockchain-service` | 证据读取、验真、重试和技术视图授权 |
| 智能合约 | 联盟组织写权限、证据唯一性、前序哈希和状态迁移 |

## 15. 权限变化

- 用户禁用后使当前会话失效。
- 角色、菜单或数据范围变更后递增授权版本并失效缓存。
- 部门变化后重新计算审批和证据数据范围。
- 已经确认的历史链上证据不因用户角色变化而删除或重写。
- 历史记录保留发生时的主体摘要，当前权限只决定是否允许查看映射后的业务信息。

## 16. 审计要求

必须记录：

- 登录失败、权限拒绝和账号禁用。
- 用户、角色、权限和部门变更。
- 审批同意、驳回、转交、撤回和重新提交。
- 证据验真、验真导出和失败任务重试。
- 合约部署信息登记和联盟链配置变更。

日志不得记录链私钥、证书正文、JWT、完整请假理由或附件原文。

## 17. 权限验收

1. 员工不能查看他人申请或证据。
2. 领导只能审批当前授权范围内且分配给本人的任务。
3. 审计员能验真但不能审批、修改申请或重试存证。
4. 运维员能查看技术状态和重试，但默认不能查看请假敏感内容。
5. 管理员不能通过普通接口读取私钥或提交任意证据。
6. 仅输入他人 `evidenceId` 或交易哈希不能绕过对象授权。
7. 前端隐藏按钮后直接调用接口仍会被后端拒绝。
8. 角色变更后旧会话不能继续使用已撤销权限。
9. 合约拒绝未授权联盟组织写入。
10. 所有重试和验真均产生可查询操作日志。
